# IT Service Desk — тикет-система для IT-отдела клиники

Веб-приложение на PHP + MySQL для приёма и обработки заявок сотрудников
клиники в IT-отдел: сотрудники создают заявки и переписываются с IT-отделом
в веб-кабинете, IT-отдел обрабатывает их в отдельном веб-приложении с
мгновенными push-уведомлениями. Никакого Telegram и cron — всё работает
напрямую через сайт.

## Состав проекта

```

/change_password.php      — смена пароля (обязательна при первом входе)

/my_tickets.php            — «Мои заявки»
/ticket.php                — диалог по конкретной заявке
/api/                       — AJAX-обработчики веб-кабинета сотрудников
/assets/                    — CSS/JS веб-кабинета
/config/config.php          — конфигурация (БД, адрес сайта, push-ключи)
/includes/                  — общий PHP-код (БД, авторизация, push)
/db/schema.sql              — структура базы данных
/db/seed_employees.sql      — список сотрудников клиники (498 ФИО)
/db/seed_it_staff.sql       — назначает роль IT-отдела двум сотрудникам
                               из общего списка (выполняется после
                               seed_employees.sql)
/storage/uploads/           — загруженные файлы/фото (создаётся автоматически)

/it/api/                    — AJAX-обработчики панели IT-отдела
/it/api/users_*.php         — администрирование сотрудников (только IT-отдел)
/it/generate_vapid_keys.php — одноразовый скрипт генерации ключей для push
```

## 1. Требования к хостингу

Проект рассчитан на самый простой shared-хостинг:
- PHP 7.3+ (проверено на 7.3.33) с расширениями: PDO/pdo_mysql, curl, gd/fileinfo, mbstring, json — на большинстве хостингов включены по умолчанию.
- MySQL 5.7+/8.0 или MariaDB 10.3+.
- Apache с mod_rewrite/mod_headers/mod_deflate/mod_expires и поддержкой `.htaccess` (AllowOverride All) — последние два модуля отвечают за сжатие и кэширование статики (быстрая загрузка страниц), без них сайт тоже работает, просто чуть медленнее грузит CSS/JS при первом визите.
- HTTPS обязателен — без него не будут работать ни push-уведомления, ни установка веб-приложения на главный экран.
- Расширение PHP **GMP** — нужно только для push-уведомлений отдельного
  веб-приложения `/it/` (раздел 3 ниже). Если его нет — весь остальной
  функционал (заявки, чат) работает как обычно, просто без push.
  Включается в панели хостинга («Select PHP Extensions» → gmp) или через
  поддержку.

## 2. Развёртывание

### Шаг 1. Загрузите файлы
Скопируйте **всё содержимое** репозитория в корень сайта (например, `public_html`)
любым способом — FTP, файловый менеджер хостинга или git.

### Шаг 2. Создайте базу данных
В панели хостинга (cPanel и т.п.) создайте:
- базу данных, например `itdesk`;
- пользователя БД с полными правами на эту базу.

Затем через **phpMyAdmin** импортируйте по очереди **три файла в этом
порядке** (порядок важен):
1. `db/schema.sql` — создаёт таблицы;
2. `db/seed_employees.sql` — добавляет 498 сотрудников клиники;
3. `db/seed_it_staff.sql` — назначает роль IT-отдела Александру Вавилову
   и Никите Павлову (они оба уже есть в общем списке сотрудников клиники —
   этот шаг не создаёт для них отдельные записи, а помечает существующие).

Пароль по умолчанию для **всех** сотрудников: `123456789`.
При первом входе система обязательно предложит сменить пароль или
оставить пароль по умолчанию.

**Если вы обновляете уже работающую установку** — после `db/schema.sql`
вам не нужно заново накатывать её; вместо этого выполните через
phpMyAdmin недостающие миграции по порядку номеров (`db/migration_*.sql`).
Актуальные на сейчас:
- `db/migration_3_web_push.sql` и `db/migration_6_push_last_error.sql` —
  таблицы push-уведомлений (без них не будет работать раздел 3 ниже);
- `db/migration_7_remove_telegram.sql` — убирает то, что было нужно
  только для старого Telegram-бота (таблицы `bot_state`,
  `notification_queue`, колонку `users.telegram_id`) и больше не
  используется;
- `db/migration_8_remember_me.sql` — таблица для постоянного входа (см.
  раздел 4 «Как это устроено»);
- `db/migration_9_user_admin.sql` — колонки `phone` и `is_active` для
  администрирования сотрудников из `/it/` (см. раздел 4 ниже);
- `db/migration_10_job_title.sql` — колонка `job_title` (должность),
  редактируется там же.

Заявки, сообщения и вложения ни одна из миграций не трогает.

**Если у вас настроен cron-задание для `bot/poll.php`** — удалите его
в панели хостинга (раздел «Cron Jobs»): этого файла больше нет, уведомления
теперь отправляются мгновенно прямо во время работы сайта, никакого
фонового скрипта по расписанию не требуется.

### Шаг 3. Настройте config/config.php
Откройте `config/config.php` и укажите:

```php
define('DB_HOST', 'localhost');       // хост БД (обычно localhost)
define('DB_NAME', 'itdesk');          // имя базы данных
define('DB_USER', 'itdesk_user');     // пользователь БД
define('DB_PASS', 'ваш_пароль');      // пароль БД

define('APP_URL', 'https://itdesk.вашклиника.ru'); // адрес сайта БЕЗ / в конце

define('ADMIN_SECRET', 'придумайте-случайную-строку'); // для служебных скриптов ниже
```

### Шаг 4. Права на папку загрузок
Убедитесь, что папка `storage/uploads/` доступна для записи веб-сервером
(обычно права `755`/`775` уже достаточно; если нет — выставьте `775`).

Готово — заявки и чат полностью работают. Дальше — раздел 3 про
push-уведомления IT-отделу (настоятельно рекомендуется, иначе IT-отдел
не узнает о новых заявках, пока сам не зайдёт на сайт).

## 3. Веб-приложение IT-отдела + push-уведомления

У IT-отдела есть отдельное веб-приложение — `https://ваш-сайт/it/` — со
своими разделами (Новые/Мои/Закрытые заявки, чат, закрепление, закрытие
с учётом дежурств, отчёт). Вход по ФИО и паролю (`123456789` по умолчанию,
со сменой при первом входе — как и у обычных сотрудников). Оно
устанавливается на главный экран телефона/компьютера как отдельное
приложение и присылает push-уведомления о новых заявках напрямую в
браузер/на экран блокировки — мгновенно, в момент создания заявки/ответа,
без задержек и без cron.

Push-уведомления есть и у обычных сотрудников клиники — в обычном
веб-кабинете (без установки на главный экран, работает в самом браузере):
когда IT-отдел отвечает на заявку, автору сразу приходит уведомление
«Ответ по заявке». Настройка одна и та же для обоих (ключи VAPID ниже) —
отдельно включать для сотрудников ничего не нужно.

### Шаг 1. Убедиться, что на сервере есть расширение PHP GMP
Оно нужно для шифрования push-уведомлений (см. раздел 1 выше). Включите
через панель хостинга или попросите поддержку. Без него `/it/` продолжит
работать как обычно (заявки, чат) — просто без push-уведомлений.

### Шаг 2. Сгенерировать ключи VAPID
Откройте в браузере:
`https://ваш-сайт/it/generate_vapid_keys.php?key=ЗНАЧЕНИЕ_ADMIN_SECRET`
(значение — то, что вы указали в `ADMIN_SECRET` в config.php). Скрипт
покажет две строки вида:
```php
define('VAPID_PUBLIC_KEY', '...');
define('VAPID_PRIVATE_KEY_PEM', "...");
```
Скопируйте их в `config/config.php`, заменив текущие пустые значения
`VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY_PEM`. После этого **удалите файл**
`it/generate_vapid_keys.php` с сервера — приватный ключ больше нигде
показываться не должен.

### Шаг 3. Готово
Больше ничего настраивать не нужно. Как только сотрудник IT-отдела откроет
`/it/` и разрешит уведомления, push начнёт приходить сразу же — сайт
отправляет их напрямую, в момент события (новая заявка, ответ,
закрепление, повторное открытие), не дожидаясь ничего по расписанию.

Если push-сервисы (Google/Mozilla/Apple) недоступны напрямую с вашего
хостинга (бывает на некоторых хостингах вместе с блокировкой других
внешних сервисов) — можно направить их через прокси-сервер:
`define('PUSH_PROXY', 'socks5h://адрес:порт');` в `config/config.php`.

### Если push-уведомления не приходят — диагностика

Если сотрудник разрешил уведомления в браузере, а они всё равно не
приходят — не гадайте, а откройте:
`https://ваш-сайт/it/diagnose_push.php?key=ЗНАЧЕНИЕ_ADMIN_SECRET`

Страница по очереди проверяет всю цепочку: расширение GMP, ключи VAPID в
`config/config.php`, есть ли вообще подписка у сотрудника в базе (если
её нет — проблема на стороне браузера/JS, не сервера), историю последних
отправок с причиной ошибки, если она была, и делает пробную отправку на
последнюю подписку. Удалите `it/diagnose_push.php` с сервера после
диагностики.

### Как сотрудники IT-отдела подключают push-уведомления

**iPhone (Safari, iOS 16.4+):** открыть `https://ваш-сайт/it/` в Safari →
кнопка «Поделиться» → «На экран «Домой»» → открыть приложение **именно с
этого значка на главном экране** (не из вкладки Safari — на iOS push
работает только у установленного таким образом приложения) → при первом
входе появится баннер «Включить уведомления?» → нажать «Включить» →
подтвердить системный запрос разрешения.

**Android (Chrome):** открыть `https://ваш-сайт/it/` → Chrome сам предложит
«Добавить на главный экран» / «Установить приложение», либо через меню
(⋮) → «Установить приложение». Дальше так же — баннер «Включить
уведомления?» при входе.

**Компьютер (Chrome/Edge/Firefox):** просто открыть `https://ваш-сайт/it/`
и войти — баннер с запросом разрешения на уведомления появится
автоматически. Можно также «установить» как отдельное окно-приложение
через значок в адресной строке браузера (необязательно для уведомлений).

Если баннер закрыли не глядя — включить уведомления позже можно через
меню (⋮) в самом приложении → «Уведомления».

**Сотрудники клиники:** уведомления работают прямо в браузере, без
установки — при заходе в веб-кабинет снизу появится баннер «Включить
уведомления, когда IT-отдел ответит на заявку?», после согласия и
системного разрешения браузера уведомления начнут приходить. На iPhone
(Safari) для push обязательно нужен установленный на главный экран сайт —
если это важно для сотрудников, добавить такую же поддержку, как у
`/it/`, можно по аналогии; сейчас у обычного веб-кабинета этого нет
(достаточно для десктопа и Android).

## 4. Как это устроено

### Сотрудники клиники (веб-кабинет)
- Вход по ФИО (с автоподбором) и паролю — **запоминается** (см. ниже),
  повторно логиниться при следующих визитах не нужно.
- «Создать заявку» — текст + вложения (фото/документы); фото перед
  отправкой автоматически сжимаются в браузере (см. раздел 5), во время
  загрузки виден заполняющийся индикатор прогресса.
- «Мои заявки» — список своих заявок со статусами (открыта/закрыта).
- Открыв заявку, сотрудник видит переписку в виде мессенджера и может
  дописывать сообщения с вложениями, пока заявка открыта; когда IT-отдел
  отвечает — приходит push-уведомление (если сотрудник его разрешил).
- Если заявку закрыли, а проблема осталась — кнопка «Открыть заявку».

### Постоянный вход
При входе (и в обычном веб-кабинете, и в `/it/`) выдаётся долгоживущая
cookie «запомнить меня» (90 дней) — заходить с паролем заново не нужно
при каждом визите, что особенно важно для установленного на главный
экран `/it/`: форма входа не должна всплывать при каждом открытии
приложения. Устроено безопасно (селектор/валидатор — общепринятая схема):
в базе хранится только хэш, а не сам токен, при каждом использовании
токен перевыпускается заново, а «Выйти» отзывает его полностью
(`includes/auth.php`, таблица `remember_tokens`).

### IT-отдел (веб-приложение /it/)
- При создании новой заявки обоим сотрудникам IT сразу приходит push
  «Новая заявка!» с превью текста и ссылкой на заявку.
- **Новые заявки** — все открытые заявки; закреплённые помечены именем
  и цветом сотрудника (Александр — фиолетовый, Никита — голубой);
  кнопка **«Забрать себе»** закрепляет заявку и рассылает push-подтверждение
  остальным сотрудникам IT;
- **Мои заявки** — заявки, закреплённые за текущим сотрудником;
- **Закрытые заявки** — вся история закрытых обращений;
- переписка по заявке — тот же диалог, что видит сотрудник клиники, с
  автообновлением каждые ~2.5 сек (приостанавливается на неактивной
  вкладке, чтобы не расходовать ресурсы зря);
- кнопка **«Закрыть заявку»**, при закрытии — чекбокс «Дежурство в
  выходные»; если отмечен — счётчик часов (по умолчанию 1 ч, ±1 ч кнопками);
- кнопка **«Открыть заявку»** — возвращает закрытую заявку в работу;
- в шапке заявки рядом с именем автора — кнопка **«📞»**, если у сотрудника
  указан телефон: открывает обычный звонок (`tel:`) средствами
  устройства (звонилка на телефоне, Skype/аналоги на компьютере, если
  такая программа установлена и назначена по умолчанию);
- пункт меню (⋮) **«Отчёт по дежурствам»** — часы по каждому сотруднику
  IT-отдела, сгруппированные по неделям;
- пункт меню (⋮) **«Сотрудники»** — администрирование учётных записей
  (см. ниже).

### Администрирование сотрудников (в /it/, меню ⋮ → «Сотрудники»)
Доступно только IT-отделу. Список всех сотрудников с поиском по ФИО/телефону/
должности вживую, по каждому — кнопка «📞» (если указан телефон). Нажатие на
сотрудника открывает карточку, где можно:
- изменить ФИО, телефон, должность (отображается рядом с именем автора
  в шапке заявки и в списке сотрудников);
- задать новый пароль (поле необязательное — если оставить пустым, пароль
  не меняется), с чекбоксом «потребовать смену пароля при следующем входе»;
- поменять роль (сотрудник / IT-отдел) и цвет бейджа для IT;
- деактивировать/восстановить доступ (чекбокс «Активен»).

Кнопка **«+ Добавить»** заводит нового сотрудника (пароль по умолчанию —
`123456789`, если не указан свой).

**Удаление** — своё или пакетное (отметить несколько галочками → «Удалить
выбранных»). Если у сотрудника ещё нет ни одной заявки/сообщения/дежурства
в истории — запись удаляется полностью. Если история уже есть (обычный
случай для «старых» сотрудников) — удалить запись без потери истории
физически нельзя, поэтому вместо удаления сотрудник **деактивируется**:
войти в систему он больше не сможет ни по паролю, ни по «запомнить меня»,
но все его прошлые заявки останутся на месте. Деактивированные отмечены
в списке значком «Деактивирован» и не могут быть выбраны заново, пока их
не восстановят обратно через тот же чекбокс «Активен». IT-сотрудник не
может деактивировать/удалить/понизить в роли сам себя — это защита от
случайной потери доступа.

## 5. Быстродействие

- Статика (CSS/JS/иконки) сжимается (`mod_deflate`) и кэшируется в
  браузере на месяц-год (`mod_expires`/`Cache-Control`) — при повторном
  визите страницы открываются мгновенно, без повторной загрузки файлов.
- Push-уведомления отправляются напрямую в момент события, без очереди и
  без cron — задержки в минуту (как раньше при опросе по расписанию)
  больше нет; несколько подписок/устройств рассылаются параллельно
  (`curl_multi`), поэтому уведомление сразу двум сотрудникам IT на
  нескольких устройствах не занимает больше времени, чем одно.
- Автообновление чата (и у сотрудников, и в `/it/`) приостанавливается,
  когда вкладка браузера неактивна, и сразу подтягивает пропущенное при
  возврате — меньше лишних запросов к серверу.
- В таблице `tickets` есть индекс по `(status, updated_at)` — список
  «Новые заявки» в `/it/` не делает полный перебор таблицы даже при
  большом количестве накопленных заявок.
- Фото перед отправкой автоматически сжимаются прямо в браузере (canvas,
  до 1600px по длинной стороне, JPEG) — фото с телефона в 5-10 МБ обычно
  становится меньше мегабайта без заметной потери качества для задачи
  (показать проблему), что особенно заметно на мобильной сети. Документы
  (PDF/DOCX/ZIP и т.п.) не сжимаются — они и так обычно уже сжаты внутри
  своего формата. Во время отправки виден заполняющийся индикатор
  прогресса загрузки (обычный `fetch()` такого не умеет — переключились
  на `XMLHttpRequest` с событием `upload.progress`).

## 6. Безопасность
- Пароли хранятся в виде bcrypt-хэшей.
- Папки `config/`, `includes/`, `db/` закрыты от прямого доступа через `.htaccess`.
- В папке `storage/uploads/` запрещено исполнение скриптов — только отдача файлов.
- Все запросы к БД выполняются через подготовленные выражения (PDO).
- Веб-приложение `/it/` использует ту же сессионную авторизацию, что и
  остальной сайт (пароль + обязательная смена при первом входе), и доступно
  только сотрудникам с ролью `it` в базе.
- Push-уведомления шифруются по стандарту Web Push (VAPID, ECDH P-256 +
  AES-128-GCM) — содержимое уведомления не видно ни push-сервису
  (Google/Mozilla/Apple), ни кому-либо ещё между сервером и браузером.
- Служебные одноразовые скрипты (`it/generate_vapid_keys.php`,
  `it/diagnose_push.php`) защищены секретом `ADMIN_SECRET` — рекомендуется
  удалять `it/generate_vapid_keys.php` сразу после использования.
- Cookie «запомнить меня» — httponly, secure (только по HTTPS), с
  ротацией токена при каждом использовании; в базе хранится только хэш
  (SHA-256) валидатора, не он сам — утечка базы не позволяет
  воспользоваться украденным токеном напрямую.
- Деактивированный сотрудник теряет доступ немедленно — при следующем
  же запросе, даже если у него была активная сессия или «запомнить меня»
  (см. раздел 4, «Администрирование сотрудников»).

## 7. Обслуживание
- Резервные копии: делайте регулярный дамп базы данных (`mysqldump`) и
  архив папки `storage/uploads/`.
- Сотрудников (ФИО, телефон, пароль, роль) теперь можно добавлять,
  редактировать и удалять прямо в `/it/` (меню ⋮ → «Сотрудники») —
  открывать phpMyAdmin для этого больше не нужно, см. раздел 4.
